# Rules for agents in this repository
- Swift feature logic lives in src-ios/Subtrees/<Name>/<Name>Feature. The Kotlin twin lives in src-android/subtrees/<name>/logic. Reducers are pure: no clock, no I/O, no platform imports.
- A behavior change starts in parity/feature-specs/<feature>.md, then the Swift scenario, then the reducers.
- The Swift scenario is the only writer of recordings. Never record from Kotlin.
- Files under parity/fixtures/ are build products. Never edit them. Regenerate with tools/duet record --feature <feature>.
- When the Kotlin lane fails a recording, fix the Kotlin twin. Never edit the fixture or the Swift side to make Kotlin pass.
- Sum types conform to CanonicalSumCodable. Their coders come from tools/duet canonical-sum. Never edit *.generated.swift.
- Every test double for a protocol marked `/// sourcery: CreateMock` is generated by tools/duet mocks. Do not write one by hand.
- Done means these pass: tools/duet lint, tools/duet verify, tools/duet record --check, tools/duet mocks --check, tools/duet protocol-run --platform both.
- Do not open Xcode or Android Studio. src-ios/App/xcodegen.yml is the source of the Xcode project.
- Reference for Duet APIs: ../duet-tutorials/docs/duet-swift-01-first-feature.md, ../duet-tutorials/docs/duet-twins-02-two-cores.md, and the -complete trees beside them.
